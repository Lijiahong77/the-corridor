### 视频化设计原则（2026-09-16 确立，后续出视频照此执行）
- **核心判断：不是所有画面都该动**——静态图把「看多久」的权力交给玩家，视频时长固定会夺走它，故视频必须少而准。
- **三类规格**（越往上越少、越关键）：
  1. 静态图（占绝大多数，不动）
  2. 行动镜（每个关键节点 1 段，角色单动作，5s）—— 如镜01 睁眼
  3. 事件镜（全场仅 1–2 段，从静到动的惊悚瞬间，5s）—— 如镜04 镜中人影转头、镜02 猫眼后的人逼近
- 镜03 照片**保持静态**（静物硬动会假，诡异感来自「静止里被发现」）
- **生成走图生视频 i2v，不是文生视频**：`create_hero_video` 传 `image_id`
  - ⚠️ **不能直接传画布图片的 node_id** —— 实测报错 `reference_node_ids must point to media nodes with resolvable urls`（2026-09-16 验证）
  - ✅ 正确链路：原图公网 HTTPS URL → `upload_image`（免费）→ 得 `image_id` + `project_id` → 再传给 `create_hero_video`
  - `project_id` 必须同时带（4510e3b5-7df9-59a5-99e1-61e8acc4e37c）；视频首帧 = 原型里那张图，切换无跳变
- **提示词只写「动作 + 运镜」，不重复画面描述**（画面已由首帧图锁定）
- 规格：`duration=5`、`model=draft`（先验，满意再升 quality）、`aspect_ratio=16:9`
- 接进互动流程：行动镜/事件镜在节点进入时自动播一次→停在末帧→出旁白与选项；**必须给「点击跳过」出口**，否则固定时长会卡住规则怪谈的快速试错节奏
- ⚠️ **TapNow 余额不足直接拦任务单**：返回 `status=blocked / reason=insufficient_balance`，**不提交、不扣费、也不返回差额**；`tapnow_status` 只报服务健康度、查不到余额 → 只能去 TapNow 网页端查看/充值

#### 智谱 CogVideoX-Flash 接口（已查准）
- 提交：`POST https://open.bigmodel.cn/api/paas/v4/videos/generations`
  Header `Authorization: Bearer <KEY>`
  body `{"model":"cogvideox-flash","prompt":"...","image_url":"<base64 或 URL>","size":"1920x1080","duration":5,"fps":30,"with_audio":false}`
- 查询：`GET https://open.bigmodel.cn/api/paas/v4/async-result/{id}` → `task_status`(PROCESSING/SUCCESS/FAIL) → `video_result[0].url`
- **免费档并发 3**；图要求 png/jpeg/jpg、不超过 5MB
- `size` 可选：720x480 / 1024x1024 / 1280x960 / 960x1280 / 1920x1080 / 1080x1920 / 2048x1080 / 3840x2160
- `duration` 仅 **5 或 10**；`fps` 仅 30 或 60
- 注意 `size`/`duration` **仅图生视频支持**；`cogvideox-flash` 不支持选 quality 模式
- 注意 base64 前缀两种写法历史上都出现过（纯 base64 / `data:image/jpeg;base64,...`）→ 脚本做了 auto 双试

#### 🐞 测试逮到 v0.1 就存在的真 bug：底图串台（靠读代码发现不了）
- 现象：切节点后，**上一个节点会被重画一遍**（旁白/文案/选项全串回上一节点）

- 证据（运行时桩打印的调用栈）：
  `goto(n3) → paint(尽头,90) → paint(书房,75)`  ← 第二次是幽灵重画
- 修复：`bg.onload = null` 用完即摘 + **`bgSeq` 单调令牌**做第二道保险（旧回调直接丢弃）；
  `playVideo` 同样加 `vidSeq` 令牌
- 💡 教训：**这类"闭包挂在 DOM 上"的 bug 读代码看不出来，必须真跑**。

### 试听页里查出的真 bug：时间条永远是 `--:--`
- 现象：卡片时间条停在 `0:00 / --:--`，只有最后一张能显示总长
- 排查：探针打出 `readyState=4`（元数据已加载）但新挂的 `loadedmetadata` 监听**永不触发** → 事件早已发生过
- **根因**：`<audio>` 在 body 里用 **`src` 属性 + `preload="metadata"`** 声明；`data:` URI 无网络延迟，
  解析器在元素之间让出事件循环时，`loadedmetadata` **在末尾脚本挂上监听之前就触发了**
- 修复（产品侧，不是改测试）：挂监听后**主动补读一次** ——
  `function syncMeta(){ if(readyState>=1 || duration>0) time.textContent = label(currentTime, duration) }`
  同时监听 `loadedmetadata` / `durationchange` / `canplay`，并立即 `syncMeta()`
- ⚠️ **教训**：`<audio>/<video>` 用属性声明 src 时，**任何"等事件"的初始化都可能漏**；
  正确姿势是"挂监听 + 立刻主动读一次当前状态"（幂等同步），而不是只等事件

### 改了什么（`_build\template.html`，共 9 处）
1. **新增 `vidLock` 状态** —— `playVideo(key, done, lockSkip)` 第三个参数；

### ⚠️ 顺手挖出的一个真漏洞（读代码发现）
`.endcard{pointer-events:none}` **挡不住子元素** —— 按钮自己写了 `pointer-events:auto`，
于是**结局卡还没浮现时，那个看不见的按钮就能点到**（点中 → 立刻 reload 重来），
位置在屏幕正中偏下（1280x720 下约 x=623, y=354）。
→ 这就是"视频还没看完就能重来"的真实原因。修复靠 `disabled` 属性
（`pointer-events` 拦不住；而且 `el.click()` / 合成事件也会绕过 pointer-events，
只有 `disabled` 能挡住真实鼠标）。

### 验证：`_build\_probe_noskip.mjs`（本次新建，12 项全通过）
- **关键手法：用 CDP `Input.dispatchMouseEvent` / `Input.dispatchKeyEvent` 发真实输入事件**，
  不要用 `dispatchEvent(new MouseEvent(...))` —— 合成事件会绕过 `disabled` 的元素级拦截，测出来是假的
- 断言链：播放中锁已上 → 连打 3 轮（点画面 + 点隐藏按钮 + 空格/回车/Esc）→
